# گزارش اعتبارسنجی جعل SNI

[English](SNI-VALIDATION.md) · [فارسی](SNI-VALIDATION.fa.md) · [Русский](../README.ru.md) · [中文](../README.zh.md)

نسخهٔ انگلیسی مرجع این سند است. آزمون‌ها برابری شناسه‌ها و پیوندها را بررسی می‌کنند.
اعتبارسنجی در 2026-09-09 روی Windows 11 x64، ساخت 22621، با Go 1.26.2 انجام شد.
این گزارش کار عبور اختیاری از DPI در `feature/sni` را پوشش می‌دهد.
این گزارش تأیید سخت‌افزار Windows 10، رفتار بسته در Linux/macOS یا عبور از محدودیت ارائه‌دهندهٔ اینترنت نیست.

نخستین اجرای کامل دروازهٔ آزمون به دلیل ترجمه‌های ناقص و سقف 30 دقیقه‌ای آزمون پیکربندی شکست خورد.
ترجمه‌ها اصلاح و دوباره بررسی شدند؛ بستهٔ پیکربندی بدون تغییر با مهلت 45 دقیقه موفق شد.
نتایج بالا ترکیب این اجراها است و ادعا نمی‌کند یک اجرای نهایی واحد از اسکریپت دروازه موفق شده است.
اسکریپت‌های مستقل نیز پس از تغییرات نهایی منبع و مستندات موفق شدند.

## پیگیری CI در 2026-09-10

نخستین اجرای CI در Linux، مجموعهٔ عادی API و مرورگر را با موفقیت اجرا کرد، اما نبود ثبت جهش‌های SNI، مجوز باز پوشهٔ دادهٔ آزمون وضعیت و مهلت 10 دقیقه‌ای بستهٔ پیکربندی را گزارش کرد.
اصلاح بعدی هر دو ایراد SNI را ثبت می‌کند، از پوشهٔ خصوصی موجود در ابزار آزمون استفاده می‌کند و مهلت هر بسته را در Linux/macOS به 30 دقیقه و در Windows به 45 دقیقه می‌رساند.
برای تغییر این حد، `CASPIAN_TEST_TIMEOUT` را تنظیم کنید؛ تمام حالت‌ها و حداقل پوشش‌ها فعال می‌مانند.
اجراکنندهٔ جهش هنگام اجرا از Git Bash، مسیر گزارش را برای Node بومی Windows تبدیل و نقل‌قول‌گذاری می‌کند.

## اثبات بومی بسته و TLS در Windows

آزمون اختیاری WinDivert فقط از سرور حلقهٔ محلی استفاده می‌کند.
بررسی می‌کند بایت جعلی وارد جریان واقعی نشود؛ نیمه‌بستن اتصال و بازتاب داده نیز آزموده می‌شوند.
سپس اتصال واقعی TLS نام مورد اعتماد سرور را بررسی و داده را بدون تغییر دریافت می‌کند.
حالت منفی مشخصاً خطای ناهماهنگی نام گواهی را الزامی می‌داند؛ شکست عمومی اتصال اثبات محسوب نمی‌شود.

یک اجرا هنگام فشرده‌سازی نصب‌کننده به مهلت 8 ثانیه‌ای کلاینت رسید.
پس از پایان فشرده‌سازی، سه اجرای متوالی هر دو آزمون بومی موفق شدند.
آزمون بسته را جدا از ساخت سنگین اجرا کنید؛ این نتیجه عملکرد محلی را ثابت می‌کند، نه کارایی زیر بار را.

با `CASPIAN_SNI_NATIVE_TEST=1` آزمون بومی را فعال کنید و فایل‌های امضاشدهٔ WinDivert را کنار فایل اجرایی آزمون قرار دهید.
فایل آزمون باید با دسترسی مدیر اجرا شود.
محیط تشخیص رقابت Go روی این میزبان به گزینه‌های پیوند فقط برای آزمون، یعنی `-linkmode=external` و `-extldflags=-Wl,--disable-dynamicbase` نیاز داشت.
این گزینه‌ها برای نصب‌کنندهٔ تولیدی استفاده نشدند.

## اعتبارسنجی باقی‌مانده

- حداقل Windows 10 پشتیبانی‌شده را روی سیستم واقعی Windows 10، همراه Mobile Hotspot و DNS دستگاه متصل آزمایش کنید.
- آزمون بومی بستهٔ Linux و macOS را روی سیستم مقصد اجرا کنید؛ ساخت میان‌سکویی آزمون مسیر بسته نیست.
- اتصال عادی و جعلی را روی شبکهٔ هدف، همراه تحویل واقعی پراکسی، DNS، اتصال مجدد و ترافیک پیوسته اندازه بگیرید.
- دادهٔ آسیب‌پذیری NuGet را دوباره بررسی کنید: بازیابی و ساخت با وابستگی‌های ذخیره‌شده موفق بود، اما سرویس ممیزی در دسترس نبود (NU1900). نسخهٔ نصب‌شدهٔ .NET SDK پیش‌نمایش بود.

[تنظیم SNI و محدودیت‌ها](SNI.fa.md)، [پژوهش منبع](THIRD-PARTY.fa.md) و [مجوزهای شخص ثالث](THIRD-PARTY.fa.md) را ببینید.

## تنظیمات مستقل تقسیم

تقسیم TCP، تقسیم رکورد TLS و جعل SNI به‌صورت مستقل انتخاب می‌شوند.
آزمون‌های محلی هر هشت ترکیب را با سرورهای واقعی TLS 1.2 و TLS 1.3 اجرا کردند.
چهار ترکیب دارای جعل SNI از WinDivert بومی Windows استفاده کردند.
هر حالت تعداد رکوردهای TLS دریافتی سرور، محتوای یکسان بارگذاری و دریافت، و رد مشخص نام نادرست گواهی را بررسی کرد.
این آزمون‌ها رفتار اتصال و رکورد TLS را تأیید می‌کنند؛ جداسازی بسته‌های TCP یا عبور از DPI در هر شبکه را ثابت نمی‌کنند.
آزمون تجزیه‌گر خواندن جزئی، پیام چندرکوردی، طول نامعتبر، ورودی ناقص و نوشتن کوتاه یا ناموفق را پوشش می‌دهد.
آزمون وضعیت و پنل، ماندگاری مستقل، مهاجرت، جایگزینی، ورودی نامعتبر و اتصال دوباره را بررسی می‌کند.
تقسیم REALITY خاموش است؛ تقسیمِ تنها به دریافت بستهٔ خام نیاز ندارد.
